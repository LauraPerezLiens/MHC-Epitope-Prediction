# NAP-CNB repository and storage audit

Inventory date 20 November 2026, Europe/Madrid. This is a read-only snapshot of the working tree including ignored local data and Git metadata. Operational logs and checkpoints can grow while the historical jobs run.

## Executive summary

The snapshot contains **510,915 regular-file entries** and **18.162 TB of allocated file blocks** (18,161,702,499,840 bytes), with **18.187 TB apparent bytes**. The dominant consumers are the historical physical representation trees under `data/`. The v2 release avoids that expansion by resolving its embeddings by exact keys. In-use historical LR and MLP outputs, caches, scalers and input derivatives are protected while those runs remain active.

The inventory counted **63 scripts** in the two requested code trees, **68 Markdown documents**, **38 .log files**, **87 project Python bytecode caches**, **7 PID markers**, and **0 named partial/temporary markers** outside ordinary bytecode. PID and incomplete markers may be evidence or live state. The two 4E reports are outside the pre-report counts.

## Measurement method

A metadata-only walk uses `lstat`/same-device traversal with directory symlink following disabled. Allocated file size is `st_blocks × 512`, counted once by device and inode. Apparent totals sum regular entries' `st_size` and may count repeated hard links. Directory blocks, symlink payloads and external targets are excluded. Filesystem compression, simultaneous activity, remote snapshots and allocation accounting mean this is an estimate of file footprint rather than a prediction of quota release. Observed hard-linked aliases: **0**. Skipped mount roots: **0**. Symlinks: **0**.

## Documentation consolidation and review order

Use the new scientific history for narrative, `docs/PIPELINE.md` for current schemas and experimental manifests, the functional READMEs for execution contracts and the local results for measurements and provenance. Keep `docs/HISTORIAL.md` as an evidence record. It includes checkpoint tables and descriptions of artifacts already removed that the new narrative cannot replace.

The root README and neural-network README describe the old concatenated workflow. Their “current” status is historical relative to D1. The reference to 14,503 chunks belongs to original source blocks and the reference to 14,499 belongs to the globally reordered corpus. Preserve that distinction in future editorial updates. The ProtT5 guide still contains prospective and stale SecondaryBERT text. The closed 3C report supersedes those status paragraphs. The model README lists historically downloaded models, while the 3B manifest identifies the pinned local ProtT5 checkpoint now needed for replay. The text in the storage inventory and in the dataset organization document should link to layer-specific evidence rather than re-copy numerical tables.

1. Preserve the release graph first. Retain `selection.json` and its signed inputs, provenance and evidence, certified embedding manifests and payloads, secondary source archives and receipts, split manifest and D1 manifest. Preserve model directories, configuration and environment specifications together.
2. Review disposable Python bytecode and the scoped duplicate list. Verify files are inactive before authorizing a deletion. Keep recipes, timestamps and provenance where they carry scientific meaning.
3. Review pilot products folder by folder. Reconcile a candidate with full-run outputs and document differences in evidence, sample universe and labels before considering cleanup. Archived IEDB calls are replay inputs whose responses can change.
4. Once old jobs finish, preserve their reviewable checkpoint, scaler, evaluation population, logs and hyperparameters. Audit how the concatenated derivative can be rebuilt byte-for-byte from retained sources or document a weaker equivalence goal and its consequences. Review any cache consolidation only after confirming path consumers and validating a restart.
5. Revisit large storage recovery last. A rebuild can be CPU- and I/O-intensive, may require temporary capacity comparable to the derivative, and can delay investigation of historical results. A retention decision needs this cost and experiment ownership in addition to directory size.
